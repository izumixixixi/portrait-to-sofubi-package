# Portrait to Sofubi Package

Create one coherent sofubi release from a single person photo. Use the bundled local extractor for the mechanical person cutout, then use the built-in image generation/editing tool for the three creative stages. Follow the installed `imagegen` skill for image-tool mechanics, image-role handling, inspection, and save behavior. Do not switch to an API/model fallback unless the user explicitly chooses it.

## Inputs

Require one clear person photo. A complete full-body source is strongly preferred, but an incomplete or cropped source may continue only through the blocking preflight confirmation below. The same photo drives both Flow 1 and Flow 2.

An additional packaging reference is optional. Never require it: the Flow 3 prompt already defines the default clear-bag-and-header-card structure.

Treat every image as having one explicit role. Do not let a style or packaging reference replace the person's identity, pose, outfit, toy sculpt, or artwork.

## Workflow

### Preflight — complete-person check before cutout

1. Inspect the original uploaded photo before running the extractor, creating a cutout, or starting any image generation. Determine whether it contains at least one complete full-body person. If the user identified a target person, evaluate that person; otherwise evaluate the clear primary subject.
2. Count the target as complete only when the body is continuously present from the top of the head or hair through both feet or shoes, with no head, torso, leg, or foot cut off by the image boundary. Natural self-occlusion, crossed limbs, or a hand hidden behind the body does not by itself make a full-body portrait incomplete; cropping by the frame does. When uncertain, treat the source as incomplete.
3. If complete, record `source_completeness = complete` and continue to Flow 1.
4. If incomplete, send this exact blocking message and nothing that implies work has already continued: `照片中没有包含一个完整全身人像，使用这个技能效果不太好。你要继续吗？` End the current turn and wait. Do not create the cutout, invoke image generation, or advance any flow before the reply.
5. If the user clearly chooses to continue, record `source_completeness = incomplete-approved` and proceed. If the user declines, stop the run without creating a cutout or generated images. If the answer is ambiguous, ask only whether to continue.
6. For `incomplete-approved`, every later flow must preserve the actually visible source/cutout boundaries. Do not extend the canvas to reconstruct, complete, or hallucinate any head, limb, clothing, shoe, or body area that was outside the uploaded frame. A result that is not complete from head to toe is expected and must not fail review for that reason. This state overrides every later requirement for a complete or fully visible person/toy, but it does not relax identity, pose, transparency, single-subject, material, typography, or packaging requirements.

### Flow 1 — person cutout to sofubi toy (图1)

1. Proceed only after preflight records `source_completeness = complete` or `source_completeness = incomplete-approved`. If the portrait is a local file, load it with the image viewer before editing unless it was already inspected during preflight.
2. Run the bundled extractor on the original local portrait: `xcrun swift scripts/extract-person-tight.swift <input-photo> <run-folder>/00-person-cutout.png --padding 0.02`. Resolve the script path relative to this skill folder. The helper uses local person segmentation, writes a real RGBA PNG, crops to the non-transparent person bounds, and retains only a 2% safety margin. It must preserve the original person's pixels rather than redraw them.
3. Inspect and validate `00-person-cutout.png` before continuing. For `complete`, require the complete head, hair, all source-visible hands, clothing edges, and feet to remain intact. For `incomplete-approved`, require every part and boundary that is visible in the original source to remain intact, but do not require or invent body areas absent from the source. In both states, require a real alpha channel with transparent pixels; no white, gray, checkerboard, scene fragment, halo, or cast shadow outside the person; and no more than 5% empty padding on any side. Do not treat a rendered checkerboard as transparency.
4. If local segmentation clips or omits a part that was visible in the original, make one background-extraction correction with the built-in image tool while repeating all preservation constraints, then run the helper on that corrected result and validate again. Correct extraction only; never synthesize a source-invisible body part. Never save an RGB image or a baked checkerboard as `00-person-cutout.png`. Do not continue to toy generation until the applicable cutout check passes.
5. After the cutout passes, render or show `00-person-cutout.png`, then ask exactly one blocking choice in Chinese: `抠图已完成。请选择玩具风格：粉色素体 / 青色素体 / dehara。` End the current turn and wait for the user's answer. Do not infer the choice from the portrait, clothing, earlier reference images, or a default. Do not start any creative generation before the reply. Skip this checkpoint only when the user explicitly tells the current run to skip confirmation.
6. Record the reply as `toy_variant = pink` for 粉色素体, `toy_variant = cyan` for 青色素体, or `toy_variant = dehara` for dehara. If the answer is ambiguous, ask only which of the three they mean. Read the shared Flow 1 prompt and exactly one matching variant reference:
   - pink: [references/flow-1-pink-material.md](references/flow-1-pink-material.md)
   - cyan: [references/flow-1-cyan-material.md](references/flow-1-cyan-material.md)
   - dehara: [references/flow-1-dehara-style.md](references/flow-1-dehara-style.md)
7. Generate a new image with the selected variant's fixed image-role map. The accepted person cutout is always the sole authority for identity, pose, action, visible silhouette, crop boundary, clothing masses, and character-specific content. For `incomplete-approved`, explicitly tell the image tool to transform only the visible cutout and not reconstruct missing off-frame anatomy or clothing. For pink/cyan, material references control only the selected vinyl color, gloss, optical depth, highlights, and studio lighting. For cyan, inspect only the turquoise-cyan vinyl regions and explicitly ignore all black, red, yellow, white, dark-painted, monster, skull, wing, tooth, eye, shoe, pose, and anatomy content. For dehara, inspect all five selected references, then pass the accepted cutout plus at most four references in one generation call so the total input count remains within the image tool's five-path limit. Prioritize 01 and 11, then choose the two references among 02, 04, and 10 that best clarify the source person's proportions and gesture. Transfer only coarse clay-master geometry, graphic hand-painting, high-gloss sofubi response, casual exaggeration, expressive but non-realistic mask-like facial construction, and rotatable shoulder seams; never transfer a reference subject, prop, animal, text, or scene. Use any unpassed selected reference only for visual understanding and QA.
8. Before generating, lock `face_mode = simple-vintage-cute` for pink/cyan or `face_mode = simple-vintage-oddball-cute` for dehara. Recognition must come primarily from the pose, headwear, a drastically simplified eyewear silhouette when present, one or two large hair masses, and the broad outfit silhouette. Pink/cyan must not reproduce anatomical eye, nose, mouth, tooth, or facial-hair details. Dehara may translate the source expression into a few bold mask-like parts—uneven dot/oval eyes, large blunt nose, graphic O-mouth, sparse block teeth, thick painted eyebrows/lines, or a flat facial-hair patch—but must not reproduce subtle realistic anatomy.
9. Make the toy unmistakably simple, vintage, cute, and hand-shaped. For pink/cyan, use the oversized head, tiny compact body, short chunky limbs, shallow face marks, and one-color unpainted blank specified by the shared prompt. For dehara, use a loose 3.5–4.5-head-tall caricature with coarse lumpy clay-master masses, an expressive oddball-cute painted face, saturated source-derived hand-painted color blocks, strong glossy soft-vinyl highlights, and separate shoulder-swivel arms. In every variant, the face must remain visibly toy-like and must never resemble a miniature portrait bust, wax figure, 3D scan, or realistic human head. Keep the white studio background. Use full-body framing only for `complete`; for `incomplete-approved`, keep the accepted source crop and show the entire available generated result without extrapolating beyond it. The person's cutout remains authoritative for pose and character content, not realistic facial anatomy.
10. Save the first result under a versioned candidate filename, then inspect the face by itself at readable size before comparing the whole toy to the portrait. For pink/cyan, reject realistic eye sockets, eyelids, irises/pupils, nose bridge/wings/nostrils, sculpted lips, teeth, facial planes, smile folds, facial-hair detail, or optical-frame detail. For dehara, allow intentionally crude protruding eye ovals with dot pupils, a large blunt nose with up to two punched-dot nostrils, an O-shaped painted lip ring or crude mouth cavity, zero to six chunky separated teeth, thick graphic eyebrows/creases, a wobbly glasses loop, and a flat moustache/beard patch. Reject any variant when features use subtle anatomical transitions, realistic dentition, skin texture, fine wrinkles, stubble, photogrammetric likeness, or a believable human portrait instead of a toy mask.
11. If the face fails step 10, perform one mandatory face-style correction before material correction. For pink/cyan, replace only the face with two small shallow eye impressions, a tiny bead-like nose nub, and one short incised mouth line. For dehara, rebuild only the face as a coarse asymmetric mask from three to six bold painted/sculpted parts chosen from its allowed eye, nose, mouth, block-tooth, eyebrow, glasses, and flat facial-hair devices; remove all subtle anatomy and realistic transitions. Preserve pose, headwear, hair mass, body, accessories, variant-specific paint and gloss, framing, and background. Reinspect the face. If it remains realistic, discard that candidate and regenerate once from the accepted cutout with the applicable `face_mode`; do not advance to material QA with a realistic face.
12. Only after the face passes, compare the whole toy with the original portrait once. Require consistency only in the broad head silhouette, non-anatomical identity cues, and variant-appropriate emotional read: gentle/neutral for pink/cyan or boldly oddball and playful for dehara. Never make a correction toward closer portrait likeness when it would add realistic facial anatomy or subtle detail.
13. Inspect surface and construction quality against only the selected variant. For pink/cyan, require coherent white-core specular highlights plus saturated selected-color turning shadows, and reject every painted or secondary color; cyan must remain uniform turquoise-cyan with no imported monster content. For dehara, separately require all three surface axes: visibly coarse/lumpy/asymmetric clay-master geometry, saturated opaque hand-painted color blocks with intentionally irregular edges and registration, and a strong medium-to-high-gloss soft-vinyl response whose bright highlights travel across both paint and rough forms. Also require narrow circular swivel seams at both visible shoulders. Reject raw clay/ceramic appearance, matte paint, monochrome blank treatment, smooth sleek geometry, copied reference features, missing visible shoulder seams, or action-figure joints.
14. If the sculpt and pose are correct but the surface treatment fails, make one targeted variant-only correction using the current candidate plus only that variant's reference image or images. For pink/cyan, correct only color consistency, oil-rich gloss, highlights, and tonal depth. For dehara, correct exactly one failed axis at a time: coarse sculpt geometry, hand-painted color treatment, strong glossy sofubi response, or simple shoulder-swivel seams. Preserve every already-approved axis, face, source pose and content, correct geometry, framing, and background. Never import a reference character, environment, exact palette, logo, text, monster/animal trait, or unrelated prop.
15. Save only the accepted candidate as `01-sofubi-toy.png`, and retain `toy_variant` for Flow 3.

Accept 图1 only when it shows exactly one toy, retains the person's recognizable action and broad visible silhouette, uses the selected variant consistently, and sits on a clean white/light-neutral studio background with no base, text, or watermark. For `complete`, the entire toy must be fully visible. For `incomplete-approved`, the full available source-derived toy result must be visible, the inherited crop is acceptable, and no missing off-frame part may be reconstructed or treated as a failure. It must read immediately as simple, vintage, cute, soft, and authentically sofubi—not realistic, elegant, or sleek contemporary designer vinyl. Person-specific recognition must come mainly from pose, headwear, simplified eyewear, hair mass, outfit, and accessories. For pink/cyan, require a primitive cute symbol face and reject readable eyelids, realistic eyes, nostrils, nose anatomy, sculpted lips, teeth, facial planes, facial-hair detail, or portrait-bust likeness; also require an aggressively simplified compact monochrome blank with rich oil-polished luster and no paint. For dehara, require a loose 3.5–4.5-head-tall coarse clay-master caricature, an expressive asymmetric oddball-cute toy-mask face with only bold non-realistic devices, saturated source-derived hand-painted color blocks, strong glossy sofubi highlights over the rough geometry, visible simple swivel seams at both source-visible shoulders, and no copied reference subject or scene.

### Flow 3 — toy plus illustration into package (图3)

1. Before designing the card, inspect the user's original photo together with `02-crayon-illustration.png` and generate one short, natural Japanese main-title phrase that reflects visible content. Set it as `main_title_ja`. Prefer the clearest visible cue in this order: action or gesture, distinctive prop or accessory, outfit or season, then overall mood. Keep it compact enough for one bold display line, normally 3–8 Japanese characters. Do not use a fixed default, a person's name unless supplied, a brand, copyrighted title, sensitive inference, occupation guess, or content not visibly supported by the photo. Do not ask the user to choose; this skill is responsible for generating the phrase. Save exactly one UTF-8 line containing only the chosen phrase as `02a-header-card-title.txt`, and retain the exact character sequence for every later validation and correction.
2. Read [references/flow-3-header-card-prompt.md](references/flow-3-header-card-prompt.md). Generate the flat header-card artwork before attempting the package photo, using this fixed role map:

   - `Image 2 = assets/flow-3-header-card-typography-reference.png; chunky display-letter proportions and left-text/right-character layout only.`
3. Create a wide, straight-on card with exactly two lines on the left—exact `main_title_ja` from `02a-header-card-title.txt` and smaller subtitle `HANDMADE SOFUBI`—and the illustrated person from 图2 on the right. Spell the generated title character by character in the image prompt. Do not copy `KRAKA`, `クラカ`, `HANDMADE PLUSH TOY`, the reference character, or its exact colors and background pattern. The title and subtitle must use the same rough crayon/oil-pastel texture, deep indigo outlines, uneven fill, and hand-drawn imperfection as the person.
4. Inspect the flat card at readable size and compare it to `02a-header-card-title.txt`. Reject a semantically generic fixed title, misspelled, duplicated, split, curved, pseudo-, or extra text; character placement on the left; text on the right; clean digital typography; or any package/plastic rendering. If either required line is wrong, make one targeted text-only correction while preserving the right-side person and the established card design. Save the accepted card as `02b-header-card-artwork.png`.
5. Read [references/flow-3-packaging-prompt.md](references/flow-3-packaging-prompt.md). Use this fixed role map:

6. If Image C is absent, remove Image-C-dependent wording and use the prompt's written packaging specification. Never block the workflow because Image C is absent.
7. Generate a realistic product photograph: the complete package lies flat on a clean white/light-neutral tabletop, viewed from top-down or a slightly angled overhead camera; a thin, wrinkled transparent bag rests naturally around the exact same three-dimensional toy result from 图1; the completed header artwork from Image A is printed unchanged on cardstock and stapled to the bag. For `incomplete-approved`, preserve 图1's inherited partial crop exactly and do not reconstruct missing toy parts. Preserve `toy_variant` exactly: pink stays bubblegum-pink monochrome, cyan stays turquoise-cyan monochrome, and dehara retains its exact saturated hand-painted palette, coarse clay-master irregularity, strong glossy sofubi finish, expressive toy-mask face, and shoulder swivel seams. 9. Save as `03-packaged-sofubi.png`. Report the chosen Japanese title and its visible cue in one concise sentence.

Accept 图3 only when the package, bag, and card are fully visible; the full available toy result is visible and clearly the same sculpt and surface treatment from 图1—pink/cyan retain exact monochrome color and oil-rich gloss, while dehara retains exact painted color blocks, coarse hand-shaped geometry, strong glossy sofubi response, expressive mask-like face, and shoulder seams; the card shows exact one-line `main_title_ja` from `02a-header-card-title.txt` over exact one-line `HANDMADE SOFUBI` on the left and the same rough-crayon person from 图2 on the right; the generated Japanese phrase is short, natural, and visibly grounded in the original photo rather than a fixed generic title; the lettering matches the person's illustration style; the package and toy lie on the table rather than stand or hang; plastic has believable wrinkles, reflections, light distortion, and contact shadows; and there is no copied branding, random typography, extra toy, box, blister pack, or CGI-looking rigid plastic. ## Review and correction

Inspect every generated image before accepting it. When one important invariant fails, make a targeted single-change correction and repeat all preservation constraints. Keep corrected outputs under versioned filenames until choosing the final file. Do not advance to Flow 3 until both 图1 and 图2 pass their checks.

If repeated corrections still cannot satisfy a critical invariant, preserve the best result, explain the remaining mismatch, and ask whether the user wants another iteration. Do not silently reinterpret the person, invent missing limbs, copy reference branding, or substitute a different packaging format. Never use correction passes to undo an approved incomplete source crop.
